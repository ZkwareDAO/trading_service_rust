# 交易验收测试

## 核心原则

**一次只执行一个测试项；每个测试项必须通过 `trade-ops` skill 执行；写操作确认自动放行；报告只写有证据的结论。**

本 skill 的定位：把人工验收测试文档转成可执行的逐项流程，调用交易助手完成操作，观察真实系统行为，产出含「预期结果 / 实际结果 / 测试结论」的报告。

## 输入 / 输出

- **输入**：用户提供的验收测试文档（Markdown / 文本，表格或自然语言均可）；用户可能同时给出文档路径。
- **输出**：`<测试文档所在目录>/<文档名>-report.md`（新文件，**不修改原文档**）；文档为粘贴内容时输出到当前目录 `trade-acceptance-report.md`。
- 报告结构固定按 `reference/report-template.md` 生成。
- 收尾时在对话中输出测试结论表（见「阶段 2：收尾汇报」）。

## 阶段 0：前置校验（任何执行之前）

1. **拆项**：通读文档，列出测试项清单——编号、原文、账号、交易所、标的、方向、数量/金额、价格、条件。
2. **账号白名单**：仅允许 `test_binance`、`test_deribit`、`ctp-simnow`（trim 后精确匹配）。
   - 文档出现其他账号名 → **立即停止，不执行任何测试项**，向用户输出：原句、识别到的账号名、白名单、请求确认。用户确认前不得继续。
   - 文档未写账号 → 按交易所映射：`binance→test_binance`、`deribit→test_deribit`、`ctp→ctp-simnow`，写入报告「前置调整表」。
   - 识别与话术细则见 `reference/execution-rules.md` §1。
3. **补预期**：文档没有「预期结果」列 → 按 `reference/test-items.md` 对应项的基准期望补全；文档已有期望 → 以文档为准，不覆盖。
4. **建骨架**：按报告模板先写出全部测试项，结论列初始为「未执行」。

## 阶段 1：逐项执行（严格串行）

对每个测试项按以下顺序执行，完成一项再进入下一项：

1. **准备 / 适配**
   - 标的不可操作或流动性差 → 换成 `reference/execution-rules.md` §3 的流动性标的，并记录「原标的 → 替换标的 + 原因」。
   - 价格与当前行情不匹配 → 用 `reference/scripts/last_price.py` 取现价后按 §4 调整（限价单、价格条件、风控阈值）。
   - 触发条件过于苛刻（如盈利 20% 回落 5%）→ 按 §4 收紧为易触发值（如盈利 0.5% 回落 1%），记录调整。
   - 所有改动写入报告「前置调整表」，**不得静默改参数**。
2. **执行**：调用 `Skill(trade-ops, args="<该测试项的完整自然语言指令>")`。
   - **禁止**绕过 trade-ops 直接调用下单 / 撤单 / 平仓 / 建规则等交易 REST 接口。
   - trade-ops 需要账户、交易所、标的等要素时，从测试文档与映射补全后再调用，不要让它追问缺省项。
3. **自动确认**：trade-ops 回显写操作确认表时，回复 `y`（用户调用本 skill 即授权本次验收的写操作）。把回显表快照记入报告。
4. **观察**：按 `reference/test-items.md` 对应项的观察步骤逐条验证；条件类测试必须等待**真实触发**，不能只看规则创建成功。
5. **判定**：`PASS` / `FAIL` / `BLOCKED`，标准见下节。
6. **清理**：停用本项创建的规则 → 撤销未成交挂单 → 平掉测试仓位；写入「清理记录表」。
7. **落报告**：立即写入该项的预期 / 实际 / 结论 / 证据，再进入下一项。

**禁止并行执行测试项，禁止把多个测试项合并成一次 trade-ops 调用。**

## 阶段 2：收尾汇报（强制执行）

全部测试项执行完毕，或明确中止后，**必须**在对话中向用户输出「测试结论表」，内容必须与报告一致、不得美化：

1. **逐项结论表**（GFM：表头 + 分隔行 + 数据行）：`# | 测试项 | 结论 | 耗时 | 关键证据/备注`
   - 结论枚举：`PASS` / `FAIL` / `BLOCKED` / `未执行`
   - 耗时口径：该项开始（含前置准备）→ 清理完成；中止项计至中止时刻；格式 `Xm`（超过 60 分钟用 `XnYm`）
   - 关键证据：一句话，含订单/规则 id、状态，或原样错误 `message`
2. **测试时间**：`测试时间：YYYY-MM-DD HH:MM ~ HH:MM（共 N 分钟）`
3. **统计**：`统计：PASS n / FAIL n / BLOCKED n / 未执行 n`
4. **异常项说明**：`FAIL` 与 `BLOCKED` 逐项给原因（原样 `message`）、影响与建议
5. **收尾状态**：本次创建的仓位/挂单/规则是否清零；存量对象是否未动；有残留必须列出
6. **报告路径**（含归档说明）

> 该表是最终交付物之一；与报告汇总表冲突时以报告为准，先修正报告再输出。

## 判定标准

| 结论 | 判定条件 |
|------|----------|
| **PASS** | 所有可验证期望全部满足，且每项都有接口返回或查询结果作证据 |
| **FAIL** | 后端返回非 0 错误码、订单/规则状态不符、数量/价格/ROI 不符、幂等不成立、触发后未按预期动作 |
| **BLOCKED** | 前置不满足、行情长时间无法触发（超时）、服务不可用、非白名单账号未获确认、文档关键要素缺失且无法消歧 |

- 超时未触发写 **BLOCKED**（附最后观测值），不得写 PASS，也不得臆测「应该会触发」。
- 后端报错时把 `message` **原样**写入实际结果，不转述、不美化。

## 条件类触发判定与清理（摘要）

- **触发判定**：先验证规则创建（状态/参数/仓位绑定），再等待真实触发。价格条件最长 10 分钟，ROI/回落/关联仓位最长 15 分钟，5 秒轮询；超时记 `BLOCKED`，附最后观测值（现价、roi、max_roi、profit_drawdown、规则状态）。
- **清理顺序**：停用本项规则 → 撤销本项挂单 → 平掉本项仓位 → 复核；只清理本项创建的对象，不动存量仓位与规则。
- **结论口径**：`PASS` = 期望全部满足且有接口证据；`FAIL` = 状态/数量/价格/阈值不符或后端返回非 0；`BLOCKED` = 前置缺失、超时未触发、服务不可用、账号未确认。
- 逐项观察与清理动作见 `reference/test-items.md`；完整规则见 `reference/execution-rules.md` §4.6、§5、§6。

## 红线

1. 非白名单账号未经用户明确确认，不得执行任何写操作。
2. 不得绕过 `trade-ops` 直接下单、平仓、撤单、创建/停用规则；行情现价脚本是唯一例外（只读查询）。
3. 不得把 BLOCKED 或超时写成 PASS；不得静默跳过测试项（无法执行也要写 BLOCKED + 原因）。
4. 请求失败必须原样记录 `message`，**不得自行改参数自动重发**（trade-ops §2.7 铁律）。基于行情的适配属于执行前的「前置调整」，必须单独记录。
5. 自动确认仅覆盖 trade-ops 的写操作回显确认；对歧义追问不得猜测——文档能消歧就按文档，不能则 BLOCKED。
6. 报告中的「实际结果」必须是观察到的系统返回或状态，不是预期复述。

## 快速参考：17 个基准测试项

| # | 测试项 | trade-ops 指令骨架 | 关键观察 |
|---|--------|-------------------|----------|
| 1 | 市价下单 | `市价开仓 …` | 订单终态 FILLED、仓位数量 |
| 2 | 限价下单 | `限价开仓 …` | 订单 NEW、挂单价 |
| 3 | 查找仓位 | `{account} 仓位列表` | 行数/字段与实盘仓位一致 |
| 4 | 创建止盈配置 | `风控 … 止盈值n%` | 规则 active、绑定仓位正确 |
| 5 | 创建回落止盈配置 | `风控 … 回落止盈n%回落k%触发` | 批量两条：arm active / trail pending |
| 6 | 创建止损配置 | `风控 … 止损值n%` | 规则 active、roi<= 阈值 |
| 7 | 重复创建回落止盈（幂等） | 同 #5 连发两次 | 规则总数是否增长、是否重复生效 |
| 8 | 创建价格风控配置 | `风控 … {sym}价格涨过/跌破 N` | condition_kind=price、阈值 |
| 9 | 创建关联仓位风控配置 | `风控 … 关联仓位{other}` | position==0、平掉关联仓后本仓被平 |
| 10 | 创建市价条件开仓配置 | `市价条件开仓 …` | 触发后真实下市价单并建仓 |
| 11 | 创建限价条件开仓配置 | `限价条件开仓 …` | 触发后挂出指定价限价单 |
| 12 | 查找盯盘规则 | `/watch-list {ex} {account} 全部` | active/pending 过滤、与 /rules 一致 |
| 13 | 回落止盈幂等：盈利/回落均不同 | 同仓位两次不同参数的回落止盈 | 两组独立链（arm1→trail1、arm2→trail2），共 4 条 |
| 14 | 回落止盈幂等：盈利不同/回落相同 | 第二次换盈利阈值、回落值相同 | 新建 arm2+trail2，两条独立链，共 4 条 |
| 15 | 回落止盈幂等：盈利相同/回落不同 | 第二次换回落值、盈利阈值相同 | 只新增 trail2，原 arm1 改指 trail2，共 3 条 |
| 16 | 价格风控不误触发（防御） | 阈值远离现价，观察窗口 | 规则 active、无平仓订单、仓位不变 |
| 17 | 关联仓位不存在拒建（防御） | `风控 … 关联仓位{不存在合约}` | 创建返回非 0 code，规则不新增 |

各测试项的完整指令模板、预期结果、观察步骤、清理动作见 `reference/test-items.md`。
