# 验收测试报告模板

报告输出为独立 Markdown 文件：`<测试文档所在目录>/<文档名>-report.md`。原测试文档不修改。

## 填写规则

1. **预期结果**：文档已有则照用，标注「来源：文档」；缺失时按 `test-items.md` 补全，标注「来源：基准」。
2. **实际结果**：只写观察到的系统返回或状态（订单状态、仓位数量、规则状态、错误 message），不写推测。
3. **测试结论**：仅用 `PASS` / `FAIL` / `BLOCKED` / `未执行`。
4. **证据**：每项至少包含执行指令、执行回显、关键接口返回摘要、时间线。
5. 时间统一 `YYYY-MM-DD HH:MM:SS`；不记录任何密钥/凭证。

## 示例片段（合成数据）

```markdown
### 测试项 5：创建回落止盈配置

- **原始测试语句**：BTCUSDT 创建回落止盈，盈利20%回落5%触发
- **前置调整**：盈利 20%/回落 5% → 0.5%/1%（现价波动下原阈值难触发）
- **执行指令**：`风控 B test_binance BTCUSDT 回落止盈0.5%回落1%触发`
- **执行回显**：

  | 账户 | 标的 | 条件 | 平仓量 | 状态 |
  |------|------|------|--------|------|
  | test_binance | BTCUSDT | ROI >= +0.5% → 盈利回落 >= 1% | 全部 | 生效中（链式） |

- **观察步骤与证据**：
  1. 2026-11-18 10:00:12 规则查询：arm `active`（roi>=0.005），trail `pending`（profit_drawdown>=0.01）
  2. 2026-11-18 10:02:30 仓位 roi 达到 0.006，arm 转 `retired`，trail 转 `active`
  3. 2026-11-18 10:05:41 profit_drawdown 达到 0.012，trail 触发平仓
  4. 2026-11-18 10:05:43 仓位数量归零，平仓订单 FILLED
- **预期结果**：批量创建 arm/trail 两条规则，触发后按全平执行（来源：基准）
- **实际结果**：两条规则创建成功；arm→trail→平仓链按预期推进，仓位归零
- **结论**：PASS
- **清理**：规则均为终态，仓位已平，无残留
```

> 示例中的价格、时间、数量均为合成值，不代表真实行情。
