# 基准测试项（17 项）

每项包含：目标、前置、trade-ops 指令模板、基准预期（文档缺预期时使用）、观察步骤、清理动作。

> 通用约定：
> - 账户只能取 `test_binance` / `test_deribit` / `ctp-simnow`（详见 `execution-rules.md` §1）。
> - 写操作由 trade-ops 回显确认，本 skill 自动回复 `y`（详见 §2）。
> - 价格与触发条件按 `execution-rules.md` §4 适配，所有调整记入报告「前置调整表」。
> - 观察必须等待真实状态变化；超时按 §4.6 判 BLOCKED。

## 测试项 1：市价下单

**目标**：验证市价单能被服务受理并按市价成交，仓位正确建立。

**前置**：无；账户需有足够保证金/可用资金。

**指令模板**

| 交易所 | trade-ops 指令 |
|--------|----------------|
| binance（数量） | `市价开仓 B 合约 test_binance BTCUSDT long 0.002 3x` |
| binance（金额） | `市价开仓 B 合约 test_binance BTCUSDT long 3x 100u` |
| deribit | `市价开仓 D test_deribit BTC-27DEC26-100000-C short 1` |
| ctp | `市价开仓 C ctp-simnow rb2701 long 1` |

> deribit 合约名以当前可交易近月平值期权为准；ctp 的 SHFE/CFFEX/CZCE 市价单由适配器转穿价限价，属正常口径。

**基准预期**
- 下单接口 `code=0`，返回 `client_order_id`；
- 订单状态经 `PLACING → NEW → FILLED`（允许短暂 PARTIAL，但 30 秒内应收敛到 FILLED）；
- 仓位列表出现该标的、该方向、数量等于订单 `filled_quantity` 的仓位；
- 无错误码。

**观察步骤**
1. 执行下单指令；
2. 用 `trade-ops` 查询订单（终态单需放开全部状态，如 `test_binance 订单列表 全部`），确认状态与成交数量；
3. 用 `trade-ops` 查询仓位，确认仓位数量、方向、开仓价；
4. 记录订单终态与仓位数量。

**清理**：`trade-ops` 平掉本项仓位（反向 reduce_only）。

**不通过示例**：订单 `REJECTED` / 60 秒仍 `NEW` / 仓位数量与成交量不符。

## 测试项 2：限价下单

**目标**：验证限价单以指定价格挂出，未成交时保持 `NEW`。

**前置**：无。

**指令模板**

| 交易所 | trade-ops 指令 |
|--------|----------------|
| binance | `限价开仓 B 合约 test_binance BTCUSDT 83000 long 0.002 3x` |
| deribit | `限价开仓 D test_deribit BTC-27DEC26-100000-C 0.085 short 1` |
| ctp | `限价开仓 C ctp-simnow rb2701 3200 long 1` |

> 价格按 `execution-rules.md` §4.2 生成：只验证挂单时买价 = 现价×0.990、卖价 = 现价×1.010。

**基准预期**
- `code=0`，订单创建；
- 订单状态 `NEW`，`order_price` 等于提交价，`filled_quantity=0`（若测试要求成交，则允许 FILLED）；
- 订单查询（默认活跃挂单）可见该单。

**观察步骤**
1. 执行限价下单；
2. 查询活跃订单，核对价格、数量、状态；
3. 记录实际提交价与现价。

**清理**：`trade-ops` 撤单（`{ex} {account} {symbol} 取消挂单`），确认状态 `CANCELED`。

**不通过示例**：价格被改写 / 状态直接 REJECTED / 下单报参数错误。

## 测试项 3：查找仓位

**目标**：验证仓位查询返回账户当前持仓，字段完整。

**前置**：最好存在至少一个仓位；无仓时验证空列表行为。

**指令模板**

| 场景 | trade-ops 指令 |
|------|----------------|
| 查全部仓位 | `test_binance 仓位列表` |
| 指定交易所 | `B test_binance 仓位列表` |
| 交易所实时仓位 | `B test_binance 交易所实时仓位` |

**基准预期**
- `code=0`，`data.list` 为数组；
- 有仓时每行含标的、方向、数量、开仓价、标记价、杠杆、盈亏、ROI；
- 无仓时为空数组，不报错；
- hedge 模式多空各一行，不净仓合并。

**观察步骤**
1. 执行仓位查询；
2. 核对返回行数、字段完整性；
3. 如条件允许，用交易所实时仓位交叉核对数量与方向；
4. 记录返回摘要。

**清理**：无。

**不通过示例**：`code!=0` / 字段缺失 / 多空被错误合并。

## 测试项 4：创建止盈配置

**目标**：验证 ROI 止盈规则创建成功并绑定正确仓位。

**前置**：该标的已有持仓；无仓时先按文档开仓（记录为前置准备）。

**指令模板**

| 类型 | trade-ops 指令 |
|------|----------------|
| ROI 止盈 | `风控 B test_binance BTCUSDT 止盈值0.5%` |
| 价格止盈 | `风控 B test_binance BTCUSDT BTCUSDT价格涨过83000` |

> 文档写「盈利 20%」时按 §4.5 收紧为 `0.5%`；价格阈值按 §4.4 贴近现价。

**基准预期**
- `code=0`，规则创建成功；
- 规则 `status=active`，`condition_kind=roi`（或 `price`），`operator>=`，`value` 与调整后参数一致；
- 规则绑定到目标仓位的 `position_id`（展示时通过仓位关联确认）。

**观察步骤**
1. 执行创建指令（trade-ops 会先查仓位并回显确认表，自动 `y`）；
2. 用 `B test_binance 风控查询` 或 `/watch-list B test_binance 风控` 查询规则；
3. 核对条件、阈值、绑定仓位；
4. 记录规则状态与参数。

**清理**：`B test_binance BTCUSDT 停用止盈止损`，确认规则 retired。

**不通过示例**：`code!=0` / 规则未绑定到正确仓位 / 条件阈值被改写。

## 测试项 5：创建回落止盈配置

**目标**：验证回落止盈链式规则按批量方式创建（arm + trail），状态正确。

**前置**：该标的已有持仓。

**指令模板**

| 类型 | trade-ops 指令 |
|------|----------------|
| 回落止盈 | `风控 B test_binance BTCUSDT 回落止盈0.5%回落1%触发` |
| 回落 + 独立止损 | `风控 B test_binance BTCUSDT 回落止盈0.5%回落1%触发，止损1%` |

> 文档写「盈利 20% 回落 5%」时按 §4.5 收紧为 `0.5% / 1%`。

**基准预期**
- 通过 `POST /api/v1/rules/batch` 一次创建两条规则；
- arm 规则：`condition_kind=roi`、`operator>=`、`value=0.005`、`action=rule:<trail_id>`、`status=active`；
- trail 规则：`condition_kind=profit_drawdown`、`operator>=`、`value=0.01`、`status=pending`；
- 两条绑定同一 `position_id`；平仓量一致（默认全平）。

**观察步骤**
1. 执行创建指令（自动 `y`）；
2. 查询盯盘规则，确认两条规则及其状态；
3. 核对 arm 的 `action` 已回填真实规则 id（服务端批量回填）；
4. 如需验证触发，见 `execution-rules.md` §5.3 四阶段观察；未触发则记录 max_roi / profit_drawdown 并判 BLOCKED。

**清理**：停用本项两条规则，确认均 retired。

**不通过示例**：只创建一条 / trail 不是 pending / 绑定仓位错误 / 批量接口报错。

## 测试项 7：重复创建回落止盈配置（幂等观察）

**目标**：观察相同回落止盈配置重复提交时是否有幂等处理，不产生重复生效规则。

**前置**：同测试项 5；先完成一次创建并记录规则 id 集合。

**指令模板**：与测试项 5 完全相同的指令，再执行一次：
`风控 B test_binance BTCUSDT 回落止盈0.5%回落1%触发`

**基准预期**
- 第二次提交后，该仓位该参数的**有效规则数量不增加**（幂等），或后端明确返回冲突错误（`code!=0` 且 message 说明重复）；
- 不得出现两套同时 `active` 的等价链式规则（否则会重复平仓）。

**观察步骤**
1. 第一次创建后，查询并记录规则 id、状态；
2. 执行第二次相同指令；
3. 再次查询规则，比较数量与 id；
4. 判定：
   - 数量不变或明确报重复 → PASS；
   - 出现重复 effective 规则 → FAIL（记录重复规则 id 与状态）；
   - 第二次因行情/环境失败 → BLOCKED。

**清理**：停用本项全部规则（含重复产生的规则）。

**不通过示例**：重复创建出两套 active 链式规则。

## 测试项 8：创建价格风控配置

**目标**：验证价格条件风控规则创建成功。

**前置**：该标的已有持仓。

**指令模板**

| 类型 | trade-ops 指令 |
|------|----------------|
| 价格涨过止盈 | `风控 B test_binance BTCUSDT BTCUSDT价格涨过83000` |
| 价格跌破止损 | `风控 B test_binance BTCUSDT BTCUSDT价格跌破81000` |

> 阈值按 §4.4 贴近现价（涨过用现价×0.998，跌破用现价×1.002）。

**基准预期**
- `code=0`；
- 规则 `status=active`、`condition_kind=price`、`operator>=`（涨过）或 `<=`（跌破）、`value` 为调整后价格；

**观察步骤**
1. 执行创建指令（自动 `y`）；
2. 查询风控规则，核对条件类型、操作符、价格；
3. 可选：等待价格触发，确认仓位按规则平仓；未触发则记录现价并判 BLOCKED（仅在文档要求验证触发动作时）。

**清理**：停用本项规则。

**不通过示例**：条件被解析成 ROI / 价格精度错误 / 绑定错误。

## 测试项 9：创建关联仓位风控配置

**目标**：验证「关联仓位被平掉时平本仓位」的联动规则。

**前置**：同时存在两个仓位——本仓位 A 与关联仓位 B（同交易所；示例 A=BTCUSDT、B=ETHUSDT，CTP 用两个品种主力合约）。

**指令模板**

| 交易所 | trade-ops 指令 |
|--------|----------------|
| binance | `风控 B test_binance BTCUSDT 关联仓位ETHUSDT` |
| deribit | `风控 D test_deribit BTC-27DEC26-100000-C 关联仓位ETHUSDT` |
| ctp | `风控 C ctp-simnow rb2701 关联仓位cu2612` |

**基准预期**
- `code=0`；
- 规则 `status=active`、`condition_kind=position`、`operator==`、`value=0`、`condition_instrument` 为关联标的；
- 关联仓位 B 平掉后，本仓位 A 被自动平掉（数量归零 / `close_time` 更新）。

**观察步骤**
1. 确保 A、B 均有持仓；
2. 创建关联规则（自动 `y`）；
3. 查询规则，核对条件与关联标的；
4. 用 trade-ops 主动平掉 B（记录指令与结果）；
5. 轮询 A，确认在其后短时间内被平掉；
6. 记录 A、B 的平仓时间与数量。

**清理**：停用本项规则；平掉剩余仓位（A 若已被联动平掉则无需重复平仓）。

**不通过示例**：B 平掉后 A 未动（超时）/ 条件标的错误 / 规则未创建。

## 测试项 10：创建市价条件开仓配置

**目标**：验证条件命中后自动下市价单并建仓。

**前置**：无（条件开仓前不应有同向持仓）。

**指令模板**

| 交易所 | trade-ops 指令 |
|--------|----------------|
| binance | `市价条件开仓 B 合约 test_binance BTCUSDT long 3x 100u BTCUSDT价格涨过83000` |
| deribit | `市价条件开仓 D test_deribit BTC-27DEC26-100000-C short 1 BTCUSDT价格涨过83000` |
| ctp | `市价条件开仓 C ctp-simnow rb2701 long 1 rb2701价格涨过3200` |

> 条件阈值按 §4.3 贴近现价以尽快触发；`condition_instrument` 必须显式可达（new 规则无持仓上下文）。

**基准预期**
- `code=0`，创建 `rule_type=new`、`action=self` 的规则，状态 active；
- 条件命中后：生成一笔市价订单，订单终态 FILLED，仓位建立；
- 规则转为 in_use / retired（不再重复下单）。

**观察步骤**
1. 执行创建指令（自动 `y`）；
2. 查询盯盘规则（全部），确认 new 规则 active、条件与下单要素正确；
3. 等待触发（≤10 分钟，5 秒轮询）；
4. 触发后查询订单与仓位，确认市价单成交、仓位数量正确；
5. 记录触发时间、订单状态、仓位数量。

**清理**：停用本项规则（若仍 active）；平掉本项建出的仓位。

**不通过示例**：规则不触发（BLOCKED）/ 触发后未下单（FAIL）/ 重复下单（FAIL）。

## 测试项 13：回落止盈幂等细分 —— 盈利阈值与回落值均不同

**目标**：验证同一仓位先后创建「盈利阈值、回落值都不同」的回落止盈时，生成两组独立链式规则，互不覆盖。

**前置**：该标的已有持仓。

**指令模板**

| 交易所 | 第一次 | 第二次 |
|--------|--------|--------|
| binance | `风控 B test_binance BTCUSDT 回落止盈0.5%回落1%触发` | `风控 B test_binance BTCUSDT 回落止盈1%回落0.5%触发` |
| deribit | `风控 D test_deribit BTC-27NOV26-63000-C 回落止盈10%回落5%触发` | `风控 D test_deribit BTC-27NOV26-63000-C 回落止盈20%回落3%触发` |
| ctp | `风控 C ctp-simnow rb2701 回落止盈10%回落5%触发` | `风控 C ctp-simnow rb2701 回落止盈20%回落3%触发` |

> 两次的 ROI 阈值与 profit_drawdown 阈值均不相同；`n%` 按 §4.5 换算为 `n/100`。

**基准预期**
- 第一次创建 arm1（active，`action=rule:<trail1>`）+ trail1（pending）；
- 第二次创建 arm2（active，`action=rule:<trail2>`）+ trail2（pending）；
- 两条链独立：arm1 仍指向 trail1，不被改写；
- 该仓位未终止规则共 4 条，均绑定同一 `position_id`。

**观察步骤**
1. 第一次创建后查询规则，记录 arm1/trail1 的 id、条件、action、状态；
2. 第二次创建后再次查询，记录 arm2/trail2，并核对 arm1 的 action 未变化；

**不通过示例**：只建一组 / arm1 被改指 / 规则数不为 4 / 两组条件混淆。

## 防御与触发强化（2026-11-24）

> 本节为 #4/#5/#6 的判定强化，并新增 #16/#17 两项防御基准；文档缺预期时以本节为准。

### #4 止盈 / #6 止损：必须验证真实触发平仓

- 规则创建成功后**必须等待真实触发**（ROI 类最长 15 分钟，5 秒轮询），不能以「创建成功」判 PASS。
- 触发后验证：规则转终态、产生真实平仓订单且 `FILLED`、仓位按平仓量归零/减少。
- 超时未触发 → `BLOCKED`，附最后 `roi` / `max_roi` / 规则状态。
- 阈值取「暧昧值」：不即时触发但保留触发机会；创建后 2 分钟内即触发视为过松，上调重测并记录；禁止 50%/5% 这类几乎不可达值。

### #5 回落止盈：三阶段判定

1. **盈利阈值到达**：arm 转终态，trail `pending → active`（原子切换）。
2. **激活后不得误平**：trail 已 active 但 `profit_drawdown < 回落阈值` 时，至少观察 60 秒——仓位数量不变、无平仓订单。
3. **回落达标真实平仓**：`profit_drawdown >= 回落阈值` 后产生真实平仓订单且 `FILLED`，仓位按 `quantity/quantity_pct` 归零/减少。
- 阈值：盈利阈值取低（易达），回落值取盈利阈值的 50%–70%（为阶段 2 留窗口）。
- 任一阶段不符 → `FAIL`；行情未达阈值 → `BLOCKED`。

### #16 价格风控不误触发（防御）

- 价格条件阈值远离现价（如现价×1.05），规则 `active` 后观察 3–5 分钟：**无平仓订单、仓位数量不变、规则不触发**。
- 误触发 → `FAIL`；观察窗内价格逼近阈值无法判定 → `BLOCKED`。

### #17 关联仓位不存在拒建（防御）

- 指令：`风控 … {主标的} 关联仓位{不存在的合约}`。
- 创建请求必须返回**非 0 code**，`message` 原样记录；规则总数不增加；主仓位不受影响。
- 返回 `code=0` 且创建成功 → `FAIL`。
