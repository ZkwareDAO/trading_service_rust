# 交易所下单校验规则（Binance / Deribit，Hyperliquid 沿用交易所校验）

> 目的：供 Rust 版交易所适配器重写参考。描述各交易所「交易规则（价格 tick、数量步长、最小值等）如何获取」以及「下单前如何校验/对齐」。
>
> 现状结论：Binance 与 Hyperliquid 走「服务启动时获取规则+ 定时更新规则(30天) → 规则存储内存 → 下单前本地校验」体系；Deribit 走「下单时按需查合约规格 → 进程内缓存 → 本地对齐」独立体系。**Hyperliquid 当前虽同步了规则，但下单路径未消费，实际依赖交易所最终校验，暂时沿用该行为。**

---

## 一、统一规则结构（B / HL 落表用，Deribit 不入表）

规则以「交易所 + 持仓类型(合约/现货) + symbol + 过滤器类型」为维度，归一为一条 `ExchangeSymbolFilter`：

- `PRICE_FILTER`：min_price、max_price、tick_size（价格最小变动单位）
- `LOT_SIZE`：min_qty、max_qty、step_size（数量最小变动单位）
- `MIN_NOTIONAL`：min_notional（最小名义额 = 价格 × 数量）

规则定时全量同步后持久化，运行时按 `(exchange, instrument_type, instrument)` 查询。

## 二、Binance

### 2.1 规则获取

- 来源：
  - 合约：`GET /fapi/v1/exchangeInfo`，只收 `contractType=PERPETUAL 且 status=TRADING`
  - 现货：`GET /api/v3/exchangeInfo`，只收 `status=TRADING`（PosType 标记为现货）
- 字段映射：
  - `PRICE_FILTER` → tick_size / min_price / max_price
  - `LOT_SIZE`（现货另有 MARKET_LOT_SIZE）→ step_size / min_qty / max_qty
  - 合约 `MIN_NOTIONAL`、现货 `NOTIONAL` → 统一归一为 min_notional
- 时机：服务启动即同步一次，之后按固定周期全量重拉刷新。
- 下单端通过注入的规则源按 `("binance", 合约/现货, symbol)` 取该 symbol 的三类过滤器。

### 2.2 下单校验伪代码

入参：order_type(LIMIT/MARKET)、price、quantity，以及该 symbol 的三类过滤器。
出参：可直接发送的字符串价格、字符串数量（Binance 数量/价格以字符串提交）。

```
function verify_binance(filters, order_type, price, quantity):

    price_filter    = filters["PRICE_FILTER"]
    quantity_filter = filters["LOT_SIZE"]
    notional_filter = filters["MIN_NOTIONAL"]

    # 规则缺失直接失败（不下发，避免交易所拒单）
    require(price_filter != null,    "PRICE_FILTER not found")
    require(quantity_filter != null, "LOT_SIZE not found")

    # ---------- 价格 ----------
    if order_type == LIMIT:
        require(price > 0, "limit order requires positive price")
        require(min_price <= price <= max_price, "price out of range")

        # 按 tick_size 的小数位数截断（floor，非四舍五入），epsilon 防浮点尾差
        price_dp    = decimal_places(tick_size)
        legal_price = truncate_to_decimal_places(price, price_dp)

        require(min_price <= legal_price <= max_price, "price out of range after truncation")
        price_str = format(legal_price, price_dp)
    else:  # MARKET：价格由市场决定，跳过价格与名义额校验
        price_str = "0"

    # ---------- 数量 ----------
    # 区间校验（带 epsilon 容差，吸收 0.009999999... 这类浮点误差）
    require(min_qty - eps <= quantity <= max_qty + eps, "quantity out of range")

    # 按 min_qty 的小数位数（即 step 精度）截断
    qty_dp    = decimal_places(min_qty)
    legal_qty = truncate_to_decimal_places(quantity, qty_dp)
    require(min_qty - eps <= legal_qty <= max_qty + eps, "quantity out of range after truncation")
    qty_str   = format(legal_qty, qty_dp)

    # ---------- 最小名义额（仅限价；市价无法预知价格，跳过）----------
    if notional_filter != null and min_notional > 0 and legal_price > 0:
        require(legal_price * legal_qty >= min_notional, "notional below min")

    return (price_str, qty_str)
```

要点：
- 一律**截断（floor 到 tick/step 精度）而非四舍五入**，截断后要重新做区间校验。
- 用一个极小 epsilon 处理浮点误差。
- 市价单只校验数量区间，不校验价格/名义额。
- 若规则源缺失（未注入），退化为直接格式化原始浮点，存在精度被拒风险。

## 三、Deribit（仅期权）

Deribit 不进统一规则表，规则来自 RPC `public/get_instrument`，按需懒加载并在进程内按 instrument 缓存（合约规格近似静态；避免每笔风控平仓单多一次 HTTP 往返）。

### 3.1 规则获取（public/get_instrument）

每个合约返回：

- `tick_size`：基础价格 tick
- `tick_size_steps[]`：**按价格区间分档的 tick 列表**（期权价格越低 tick 越小），元素为 `{above_price, tick_size}`
- `qty_tick_size`：下单数量（张数）的最小变动单位 —— 数量步长首选
- `min_trade_amount`：最小可交易张数；当合约未提供 qty_tick_size 时作为步长回退
  - 注意二者不同义：例如最小 10、步长 1，则 15 合法
- `contract_size`：合约乘数
- kind / 到期日等

缓存失效：下单被交易所以「数量非法」拒绝时，删除该 symbol 的缓存步长，下一笔重新拉取当前值（无需重启）。价格 tick 因依赖价格档位，定价时实时从（已缓存的）合约规格里按价位选取。

### 3.2 数量校验/对齐伪代码

```
function aligned_amount(symbol, qty):
    step = cached_size_step(symbol)
    if step == null:
        details = get_instrument(symbol)          # 懒加载
        step    = details.qty_tick_size
        if step <= 0: step = details.min_trade_amount
        cache(symbol, step)

    if step <= 0 or lookup_failed:
        warn("sending quantity unaligned")
        return qty                                # 元数据故障不挡单，交给交易所兜底

    aligned = round_to_multiple(qty, step)        # 对齐到步长整数倍（十进制精度工具，防浮点尾差）
    if abs(qty - aligned) 超过浮点噪声阈值:
        warn("qty not a multiple of step; 对齐后会残留未平仓位", residual = qty - aligned)
    return aligned
```

要点：
- 数量单位是「张」，价格单位是期权费（以 BTC 计）。
- 对齐到步长整数倍；查不到规则时**原样发出**，把最终校验权交给交易所，不让元数据故障阻断风控平仓。
- 因取整可能留下残余仓位，超出浮点噪声的偏差要告警。

## 四、Hyperliquid（暂时沿用交易所校验）

- 规则来源已具备：POST /info `type=meta`，可推导数量步长 `10^(-sz_decimals)` 与价格 tick（5 位有效数字规则），并有定时同步落表。
- **但当前下单路径未使用这些规则做本地校验/截断**：
  - 市价单（以 IOC 限价单实现）价格由 SDK 的滑点价格计算（内含 tick 处理）；
  - 数量原样透传。
- 因此最终精度合法性由交易所返回决定。Rust 版可先保持「依赖交易所校验」，后续再决定是否接入本地步长/tick 截断。

## 六、内存存储的交易规则数据模型（当前范围：Binance / Hyperliquid / Deribit）

> 本节定义下单校验所依赖的规则在**内存中的存储形态**。当前只服务 crypto 三家（Binance 现货+U 本位永续、Hyperliquid 永续、Deribit 期权）；大宗/国内期货/股票的规则**暂不建字段**，只保留枚举位与逃生舱（见 6.7），等接入时再升格。

### 6.1 定位与原则

1. **纯内存缓存，不落 CSV**。交易规则是交易所发布的公开静态数据，随时可重拉，不属于 account/order/position 这类业务 model：没有 `id`、`deleted`、`created_at/updated_at`，不参与日切快照与内存恢复；进程重启后重新同步即可。
2. **内存是校验路径的唯一读取面**。适配器把各交易所原生规格归一化为同一种行结构写入，校验器只认这一种结构，不感知交易所差异。
3. **一行一标的，整行不可变替换**。键为 `(exchange, instrument_type, symbol)`。值包 `Arc`，刷新端构造新行整体 put；读端克隆 `Arc` 后无锁使用，不会读到「新 tick + 旧 step」的撕裂组合。
4. **金额/精度字段一律定点 `Decimal`**，与 order/position 保持同域，禁止 f64 参与步长、名义额运算。
5. **两家填充策略，一张表**：Binance/HL 启动全量 + 定时重拉；Deribit 懒加载 + 按拒单失效。对外暴露同一个按 key 查询的接口，策略差异只在写入侧。

### 6.2 存储形态

```
OrderRuleTable = DashMap<OrderRuleKey, Arc<OrderRule>>

OrderRuleKey {
    exchange:        &str,             // "binance" / "hyperliquid" / "deribit"
    instrument_type: InstrumentType,   // spot / futures / option
    symbol:          String,           // 交易所原生符号：BTCUSDT / BTC / BTC-27DEC26-100000-C
}
```

- Binance/HL：全量同步任务按 key 整批 put 替换；查不到 = 规则缺失，Binance 路径直接判失败不下发。
- Deribit：查询未命中时触发一次 `public/get_instrument` 懒加载并放入同一张表；被交易所以「数量非法」拒单时删除该行，下一笔重新拉取（见第三节）。
- 溯源字段（来源、拉取时间、版本）随行存放，**只服务刷新/过期决策，不参与校验**。

### 6.3 字段表（`OrderRule`）

只保留三家当前真实消费的字段；「必填」针对在营标的，`Option` 为该交易所不提供或不适用。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| exchange | string | 是 | 交易所标识：binance / hyperliquid / deribit |
| symbol | string | 是 | 交易所原生符号，与订单 `instrument` 同形 |
| instrument_type | enum | 是 | 当前只会出现 `spot` / `futures`（Binance U 本位永续，系统统一口径）/ `option`；枚举另预留 `perpetual`/`equity`/`fund`，其中 `perpetual` 当前不产出 |
| underlying | string? | 期权必填 | 标的本体，Deribit=BTC；现货/永续留空 |
| qty_unit | enum | 是 | 数量口径：Binance/HL=`base`（币），Deribit=`contract`（张）；`share` 已预留 |
| multiplier | Decimal | 是 | 1 个下单单位对应的标的量：现货/永续=1，Deribit 期权=`contract_size`；敞口 = qty × multiplier |
| quote_currency | string | 是 | 报价币种：USDT / USD / BTC（期权费以 BTC 计） |
| settle_currency | string | 是 | 结算/盈亏币种；position 冗余此字段 |
| price_tick | Decimal? | 单档时必填 | 单档价格步长（Binance `tick_size`；HL 无固定 tick，留空走 sig_digits） |
| price_tiers | []PriceTier? | 分档时必填 | 分价位步长表（Deribit `tick_size_steps`）；与 price_tick **互斥** |
| price_min / price_max | Decimal? | 否 | 价格允许区间（Binance PRICE_FILTER） |
| price_max_sig_digits | u8? | 否 | 价格最大有效数字位数（Hyperliquid=5）；与 price_tick 是两种价格精度口径 |
| qty_step | Decimal | 是 | 限价数量步长：Binance `stepSize`、HL `10^-sz_decimals`、Deribit `qty_tick_size`（回退 `min_trade_amount`） |
| qty_min / qty_max | Decimal? | 否 | 限价数量区间（Binance LOT_SIZE；Deribit 只有 min_trade_amount 时仅填 min） |
| market_qty_step / market_qty_min / market_qty_max | Decimal? | 否 | 市价数量档（Binance 现货 MARKET_LOT_SIZE）；为空表示与限价档相同，校验市价单时回退 qty_* |
| notional_min / notional_max | Decimal? | 否 | 名义价值（qty × price）区间：Binance MIN_NOTIONAL/NOTIONAL；HL/Deribit 留空 |
| notional_min_to_market / notional_max_to_market | bool | 否 | Binance 现货 NOTIONAL 的 `applyMinToMarket`/`applyMaxToMarket`；默认 false，仅 Binance 现货可能为 true |
| expires_at_ms | i64? | 期权必填 | 到期时间毫秒（Deribit `expiration_timestamp`）；现货/永续为空；供 position.expires_at 冗余 |
| source | string | 是 | 数据来源标识：`binance:exchangeInfo` / `hyperliquid:meta` / `deribit:get_instrument` |
| fetched_at_ms | i64 | 是 | 拉取时间毫秒，判断缓存新旧（B/HL 定时刷新；Deribit 规格近似静态，仅拒单失效） |
| spec_version | string? | 否 | 交易所定义版本（Binance exchangeInfo 带 version），用于比对是否需要替换 |
| extra | map<string,string> | 否 | 逃生舱：暂未升格为正式字段的交易所怪约束（如 PERCENT_PRICE、icebergParts），仅透传记录，校验器不消费 |

`PriceTier`（Deribit 分档，顺序即交易所返回顺序）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| above_price | Decimal | 委托价 ≥ 该值时适用本档（对应 Deribit 的 `above_price`，首档通常为 0） |
| tick | Decimal | 该档价格步长 |

取档规则：取所有 `above_price <= price` 中门槛最高的一档；定价时按委托价实时选档（开仓被动价：买 mark−5tick / 卖 mark+5tick；平仓对手价；各选各的档）。

| 行字段 | Binance（fapi / api exchangeInfo） | Hyperliquid（info meta） | Deribit（get_instrument，懒加载） |

### 6.5 Rust 结构草图（trading-models，Decimal + serde）

    // —— 数量精度 ——

    #[serde(default)]

    #[serde(default)]

    #[serde(default)]

### 6.6 校验消费方式（与第二~四节对齐）

- **Binance**：取出行后要求价格/数量档必须存在，缺失即判失败；限价按 `price_tick` 截断（floor，非四舍五入）后重检 `price_min/max`，数量按 step 截断后重检区间，限价比对 `notional_min`；市价只查 `market_qty_*`（空则回退 `qty_*`），名义额按两个 `*_to_market` 开关决定是否校验。
- **Deribit**：取行未命中则懒加载；数量对齐 `qty_step` 整数倍，取不到步长时**原样发出**交给交易所兜底（元数据故障不挡风控平仓）；价格 tick 按委托价从 `price_tiers` 实时选档。
- **Hyperliquid**：行照常同步落表，当前下单路径不消费（市价走 SDK 滑点价、数量透传），最终合法性由交易所判定；字段先备齐，后续接入本地截断时无需改表结构。

### 6.6 下单前校验的三层划分

按**是否依赖 IO** 分层，纯计算与取数/动作分离，便于单测：

1. **core 纯校验 `OrderRule`（无网络/SDK，可 TDD）**：入参 `(&OrderRule, &OrderCheck)`，出对齐后的价/量。
   - Binance：tick 截断/区间/名义额，违规拒发；Deribit：数量取整到步长、市价开仓漂移成被动价（买 mark−N tick / 卖 mark+N tick）、平仓买一卖一价差闸门；Hyperliquid：本地不强校，透传交服务端。
   - 行情（mark/bid/ask）经 `OrderCheck.market` 传入，**取数不在这里**。
2. **venue `place_order`（RestApi 实现）**：负责取数与发单——Deribit 先拉 mark/盘口再喂 `OrderRule`，Binance 直接校验，HL 跳过本地校验。差异在各所内部消化，不另起 trait。
3. **service 编排层（业务/风控，跨所）**：余额不足→加杠杆等需查余额、读风控配置、调 `set_leverage` 的策略放这里（见 plan 扩展清单），**不进 `OrderRule`**。

> 时机：现仅 Binance 一份实现，暂不抽 trait；接入 Deribit 出现第二份差异实现时再引入 `OrderRule`，把 `verify_binance` 平移为 `BinanceRules`。

### 6.7 扩展预留（现在不实现）

- **合约形状扩展**：`InstrumentType` 已含 `futures/equity/fund`，`QtyUnit` 已含 `share`；接入国内期货/美股时新增对应交易所的归一化 fetcher 写同一种行，必要时再把家族特有约束（保证金率、平今平昨、盘前盘后、交易时段/节假日、大宗门槛）从 `extra` **升格为正式字段**——在此之前一律不建。
- **新精度口径**：价格的三种口径（固定 tick / 分档 tiers / 有效数字）已覆盖三家；未来出现新口径优先评估能否归入三者，再考虑新字段。
- **新交易所**：实现「原生规格 → OrderRule」映射并复用同表与同一校验内核，不改读端。
- **被刻意推迟、不进当前模型的字段**：listed_at、strike/option_type（可从原生 symbol 解析）、price_max_decimals（可由 tick 推导）、现金下单步长（quoteOrderQty）、动态价格带（PERCENT_PRICE，暂存 extra）、订单类型/TIF 能力声明、交易时段/节假日日历、杠杆/保证金率、持仓限额。
