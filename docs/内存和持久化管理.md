## 内存和持久化模块

### 模块架构
1. 对外有统一的接口，对此项目的所有model 内存进行管理，以及内存数据的csv 持久化
2. 所有model 都可以通过此模块进行对内存的CRUD，即增删改查。
3. 单独针对一个model，存在一个总表，总表存在读写算，表内数据每行数据都存在一个子锁。
4. 该模块为项目的某个模块，但是需要外面调用此模块功能
### 测试mock设计
支持对每个model 进行CRUD，同时多个对内存并发存储和持久化

### 内存和持久化设计
内存设计
1. 支持model的扩展，每个model 都需要有一个标识为删除的字段，如 deleted ， 默认为0 ，1 为已经删除
2. 启动时根据持久化数据，对内存进行恢复
3. 每个model 都存在 created_at 和updated_at 字段， 此字段model自动更新，且为时间戳，达到毫秒

持久化设计
1. 定时根据models内存进行持久化存储，当时间到了第二日，需要新的日期持久化；
2. 持久化存储文件格式 {day}/{account_name}/{model}.csv
3. 在存储新一日的数据时，需要将model 字段前一日标识为deleted 为1 的model 在内存中清理

数据查询
1.优先查询内存中model 数据 deleted 为0 的数据
2.特别说明如果需要读取每日持久化数据时，把每日数据都读取，并去重，取最新状态

| --- | --- | --- |
| id | u64 | 主键 |
| account_id | u64 | 所属账户 |

| margin | decimal | 实际占用保证金/本金 = notional / leverage，定点 |
| settle_currency | string | 结算/盈亏币种（USDT/USD/BTC…），冗余自 spec；pnl 以此币种计 |
| pnl_value | decimal | 未实现盈亏（以 settle_currency 计），定点 |
| realized_pnl | decimal | 已实现盈亏（减仓/平仓累计），定点 |
| roi | decimal | 未实现盈亏率（比率而非百分数：+12.34% 存 0.1234；margin=0 等不可定义时存 0），定点 |
| max_roi | decimal | 持仓期内最高 roi（盈利峰值，只增不减；从未盈利为 0），定点 |

#### WatchRule 盯盘/风控规则表

> 由策略端创建、随仓位生命周期推进，是 `Order.rule_id` / `Position.rule_id` 外键指向的权威行。
> 账户作用域表，持久化于 `{day}/{account_name}/watch_rule.csv`。
> 注意与 `OrderRule`（交易所发布的公开下单规格，纯内存、不落盘）区分——二者同名近义但不是一回事。
>
> 「命中后做什么」由两个正交字段决定：
> * `rule_type` 决定执行自身时的业务动作，也决定 `quantity` 的语义（`new`=开仓量；`risk`=平仓绝对量）；
> * `action` 决定命中后是执行本规则自身（`self`），还是转而激活另一条链式规则（`rule:{id}`）。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| id | u64 | 本地主键 |
| position_id | u64 | 对应仓位 id；开仓规则可为 0 |
| rule_type | enum | 规则类型：`new`（开仓，携带下单要素）/ `risk`（风控减/平仓）；CSV 存小写 |
| condition_kind | enum | 条件主类：`roi` / `price` / `position` / `profit_drawdown`；CSV 存 snake_case |
| condition_instrument | string? | price_/position_ 条件的标的后缀；为空表示本仓位标的（roi 等忽略）。磁盘上与 condition_kind 组合为 `condition_name`：`roi` / `price_{instrument}` / `position_{instrument}` / `profit_drawdown` |
| operator | string | 比较操作符：`>=` / `<=` / `>` / `<` / `==`，由风控引擎解释 |
| value | decimal | 条件阈值，定点 |
| action | string | 命中动作的磁盘编码：`self`（执行本规则）/ `rule:{id}`（激活另一条链式规则） |
| status | enum | 生命周期：`active` 生效中（默认）/ `pending` 待链式激活 / `in_use` 已命中执行中 / `retired` 已终止（唯一终态）；CSV 存小写 |
| exchange | string | 下单交易所（new 规则消费；risk 留空） |
| account_id | u64 | 所属账户（账户作用域） |
| instrument | string | 目标代币（new 规则消费；risk 留空） |
| instrument_type | enum | 合约形状：`spot` / `futures`（Binance U 本位永续）/ `option` / `equity` / `fund`；`perpetual` 预留不产出。旧快照缺列按 `futures` 恢复 |
| side | enum | 开仓方向 BUY/SELL：仅 `new` 消费；risk 平仓方向由持仓反向推出。旧快照缺列按 BUY 恢复 |
| price | decimal | 下单价格，定点（市价单为 0） |
| quantity | decimal | 下单数量，语义随 rule_type：new=**开仓数量**；risk=**平仓绝对数量**（按比例平仓时为 0，数量取 quantity_pct）。与 quantity_pct 互斥，定点 |
| order_type | enum | 订单类型：new=开仓单类型，risk=平仓单类型；limit / market / stop_market / take_market |
| quantity_pct | decimal | risk 按当前持仓比例减/平仓（比率：全平=1，半仓=0.5）；仅比例平仓使用，此时 quantity=0；绝对数量平仓与 new 不消费，缺省 1，定点 |
| leverage | u64 | 开仓杠杆：仅 `new` 消费（命中下单前先 set_leverage）；risk 不读，缺省 1 |
| deleted | bool | 软删除：0=活跃，1=终止态 |
| created_at / updated_at | u64 | 创建/更新时间戳（毫秒） |

> WatchRule 没有 `exchange_update_time`：它不是交易所回报对象，状态只由本地规则引擎推进。

### 核心设计原则（外部读写内存）
1. 内存是唯一可信数据源（Source of Truth）
2. CSV 只是持久化快照（Persistence / Recovery）
3. 外部读写只操作内存，不直接碰 CSV
4. 并发安全的内存存储 + 后台/按需持久化

##### 设计约束
1. 不要使用channel来在任务传递数据
2. 支持多 strategy / 多交易所实例高并发接入
