# 行情数据模型规范（Rust）

> 本文件是新 Rust 行情服务的 **model 规范**：定义需要保存的数据结构、字段类型、组织形式与数据来源。
> 不涉及并发原语、锁与持久化实现（那些在工程落地时另行决定）。

---

## 1. 标识模型

用强类型标的作为全局唯一 key，从根上区分"同名但不同市场/交易所"，并收口各交易所的符号差异。

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum Venue {
    BinanceSpot,
    BinanceFutures,   // USDⓈ-M U 本位永续
    Hyperliquid,
    Deribit,
}

#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum MarketKind { Spot, Futures, Option }

/// 全局唯一标的。
/// symbol 存"规范化符号"：Binance 原样(BTCUSDT)、Hyperliquid 裸币名(NEAR)、
/// Deribit 完整 instrument 名(ETH-18SEP26-2550-P)。
#[derive(Clone, PartialEq, Eq, Hash, Debug)]
pub struct Instrument {
    pub venue:  Venue,
    pub kind:   MarketKind,
    pub symbol: String, // canonical
}
```

交易所原始 wire 符号与 `Instrument` 的互转由各 venue 的 codec 负责（Hyperliquid 的 `NEAR <-> NEARUSDC` 去/补后缀在这里处理，不泄漏到存储 key）。

## 2. 行情数据结构

价格数值默认 `decimal`；时间统一毫秒时间戳。

```rust
pub type Price = decimal;

/// 买一/卖一盘口。任何字段为 None 表示该侧无报价或未订阅。
#[derive(Clone, Copy, Debug, Default)]
pub struct TopOfBook {
    pub bid: Price,
    pub ask: Price,
}
```

### 2.1 核心结构：`Quote`

每个 `Instrument` 对应一个 `Quote`。字段全部按需填充，未取到/未订阅即为 `None`。

| 变量名 | 类型 | 含义 | 主要来源 |
|---|---|---|---|
| `last` | `Option<Price>` | 最新成交价 | Binance 现货 miniTicker；其余可选 |
| `mark` | `Option<Price>` | **标记价，估值/风控主口径** | B 合约 markPrice 流、H `activeAssetCtx.markPx`、D ticker |
| `mid` | `Option<Price>` | 买卖盘中点 | H allMids；D 可由 bid/ask 推导 |
| `book` | `Option<TopOfBook>` | 最佳买/卖价（可成交价口径） | **当前仅 D ticker 填充**；B/H 结构保留、暂不订阅 |
| `ts_exchange_ms` | `i64` | 交易所消息时间戳（无则 0） | 各频道消息头 |
| `ts_recv_ms` | `i64` | 本地接收时间戳（新鲜度判定主依据） | 本地写入 |

```rust
#[derive(Clone, Copy, Debug, Default)]
pub struct Quote {
    pub last:            Option<Price>,
    pub mark:            Option<Price>,
    pub mid:             Option<Price>,
    pub book:            Option<TopOfBook>,
    pub ts_exchange_ms:  i64,
    pub ts_recv_ms:      i64,
}
```

> 不设单调 `version`：单连接内消息保序，新鲜度由 `ts_recv_ms` 判定；重连乱序若将来需要处理，用"连接代际（epoch）丢弃旧连接消息"解决，而不是给每个标的维护计数器。

`Quote` 上的取值规则（集中实现，避免各处各写一套口径）：

```rust
impl Quote {
    /// 估值/风控价：mark > mid > last；全 None = 无价。
    pub fn valuation_price(&self) -> Option<Price> {
        self.mark.or(self.mid).or(self.last)
    }
    /// 可成交价：平多(is_short=false)吃 bid，平空(is_short=true)吃 ask。
    /// B/H 当前 book 为 None（走交易所原生市价单），仅 D 用本地对手价转限价。
    pub fn executable_price(&self, is_short: bool) -> Option<Price> {
        self.book.map(|b| if is_short { b.ask } else { b.bid })
    }
    /// 新鲜度：按本地接收时间判定，过期数据不得参与风控。
    pub fn is_fresh(&self, now_ms: i64, max_age_ms: i64) -> bool {
        self.ts_recv_ms != 0 && now_ms - self.ts_recv_ms <= max_age_ms
    }
}
```

## 3. 各交易所数据来源

### 3.1 Binance 现货（BinanceSpot）

现货不存在标记价，`mark` 恒为 `None`。

| 数据 | 来源频道 | 更新方式 | 填充字段 |
|---|---|---|---|
| last | `!miniTicker@arr`（全市场，1s） | 全量快照 | `last`（取 close price） |

端点：现货 WS 主机。现货与合约是不同主机，**不能用一条原生连接同时订**。
盘口：`book` 结构保留，**当前不订阅**；将来加 `!bookTicker` 即向 `book` 填充。

### 3.2 Binance U 本位合约（BinanceFutures）

风控估值使用**标记价流**，不使用 miniTicker 充当估值价。

| 数据 | 来源频道 | 更新方式 | 填充字段 |
|---|---|---|---|
| **mark** | `!markPrice@arr@1s`（全市场，1s） | 全量快照 | `mark`（取 markPrice） |
| last（一般不需要） | `!miniTicker@arr` | 全量快照 | `last`，仅在确有展示需求时加订 |

端点：合约 WS 主机（与现货各自一条物理连接，写入同一张 `Instrument -> Quote` 表）。
盘口：markPrice 流**不含** best bid/ask，`book` 结构保留但**当前不订阅**；将来需要时在**同一连接**上加订 `!bookTicker`（建议只对持仓/风控子集订 `<symbol>@bookTicker`，避免全市场逐笔推送）。
下单：Binance 支持**原生市价单**，不需要本地对手价，因此 `book=None` 不影响下单。

### 3.3 Hyperliquid（Hyperliquid，永续）

分两层：全市场 mid 做发现、持仓子集拿 mark。盘口暂不订阅。

| 数据 | 来源 | 更新方式 | 填充字段 |
|---|---|---|---|
| 全市场 mid | WS `allMids`（无参数，事件驱动） | 全量快照（整表） | `mid`（key 为裸币名） |
| **mark** | WS `activeAssetCtx`，**逐 coin 订阅**（仅持仓+风控所需） | 单标的增量（字段级 merge） | `mark`(markPx)、`mid`(midPx) |
| 全量 mark 初始化或兜底 | REST `info` 的 `metaAndAssetCtxs`（一次返回所有 perp） | 周期性拉取 | 批量预热/校正 `mark` |

说明：
- **没有"一条 WS 全市场推送 mark"的频道**；`allMids` 只有 mid，`activeAssetCtx` 必须带单个 coin。需要全市场 mark 时用 REST 批量接口，不要对全部币种发 WS 订阅。
- 强平/保证金口径是 `markPx`（受 `oraclePx` band 约束），不是 `midPx`；估值必须用 `markPx`。
- 盘口：`book` 结构保留但**当前不订阅 `l1Book`**，`book=None`；需要平仓价差保护时再对持仓子集加订 `l1Book`（与 `activeAssetCtx` 复用同一连接）。
- 下单**无原生市价单**：HL 协议只有 limit，项目用 **Limit + IOC + 滑点价**模拟市价；参考价在下单时由 SDK 经 REST `AllMids` 取 **mid**，再按默认 5% 滑点向有利方向偏移。该参考价不读本地 `book`，故不订阅 l1Book 也能下单。

### 3.4 Deribit（Deribit，期权）

| 数据 | 来源 | 更新方式 | 填充字段 |
|---|---|---|---|
| mark / bid / ask | WS `ticker.{instrument_name}.100ms`（持仓+rule 动态子集，100ms） | 单标的增量 | `mark`、`book.bid/ask` |
| 同字段兜底 | REST `public/ticker`（单标的） | 下单/价差检查或 WS 失效时按需 | 同上（mark、book） |

说明：
- 频道消息**原子地同时带** mark 与 best bid/ask，一条消息即同一时刻的一组值，字段级写入即可（mark 与 book 不存在跨频道时间不齐问题）。
- 订阅为动态子集，随建仓/平仓/rule 变更增删，重连后整体重放。
- Deribit 无原生市价单，下单取可成交价、平仓前价差检查使用 `book`（或下单前一次 REST 实时刷新），与风控用的 `mark` 分离。

## 4. 字段可得性总表

| 字段 | Binance 现货 | Binance 合约 | Hyperliquid | Deribit 期权 |
|---|---|---|---|---|
| `last` | ✅ miniTicker | ⬜ 可选 miniTicker | ⬜（可由 mid 近似） | ⬜ 可选 |
| `mark`（风控主口径） | — 不存在 | ✅ markPrice 流 | ✅ activeAssetCtx | ✅ ticker |
| `mid` | — | ⬜ | ✅ allMids | ⬜（可由 book 算） |
| `book.bid/ask` | ◻ 暂不订阅（bookTicker） | ◻ 暂不订阅（bookTicker） | ◻ 暂不订阅（l1Book） | ✅ ticker（自带） |
| 订阅范围 | 全市场 | 全市场 | 全量 mid + 持仓子集 mark + rule子集 | 持仓/rule 子集 |
| 物理连接 | 现货主机 1 条 | 合约主机 1 条 | 1 条（多频道复用） | 1 条（多频道复用） |

✅=订阅保存　◻=结构保留但当前不订阅　⬜=可选/按需　—=该市场不存在
