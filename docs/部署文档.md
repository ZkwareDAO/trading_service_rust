# 部署文档

本服务（trading_service_rust）生产环境部署手册。部署前请先通读全文。

---

## 1. 生产 vs 测试 的关键差异

| 维度 | 测试（本地） | 生产 |
|---|---|---|
| 交易所网络 | account.csv 中 `is_testnet=1` | **`is_testnet=0`**（deribit→www.deribit.com 主网） |
| 南向鉴权 | `--south-dev-insecure` | **禁止带该参数**，强制 HMAC 签名 |
| 账户 secret | 可明文（启动告警） | **必须 `enc.v1.*` 加密** |
| 传输 | ws:// | **wss://（TLS）**，由 Nginx/Caddy 终结 |
| 企业微信 | 测试群机器人 | **生产群机器人**（五个通道见 §3.4） |

> **出站代理**：多数生产机可直连外网，无需配置。若机器须经代理访问交易所，
> 部署脚本会自动探测执行用户的 `http_proxy`/`https_proxy` 环境变量（或
> `~/.proxy_env` 文件）注入 systemd 单元——**`https_proxy` 必须存在**（binance 等
> 均为 https/wss 目标，仅 `http_proxy` 对 TLS 请求无效）。排查连接超时先看
> `systemctl show trading-service -p Environment`。

## 2. 目录与路径说明

/opt 一体化布局（一键脚本 §3.0 固定使用）——一切都在安装目录内，卸载/迁移一目了然：

| 路径 | 说明 |
|---|---|
| `/opt/trading_service_rust/bin/trading-service` | 服务二进制（脚本安装） |
| `/opt/trading_service_rust/bin/manage.sh` | 管理入口（软链到 `/usr/local/bin/trading-service`） |
| `/opt/trading_service_rust/bin/start.sh` | 首次启动/配置变更后的重启入口（`deploy.sh` 不启动服务） |
| `/opt/trading_service_rust/lib/ctp/` | CTP 运行库（`deploy.sh` 从仓库 vendored 安装） |
| `/opt/trading_service_rust/conf/venue.toml` | 交易所可调参数（缺失用内置默认） |
| `/opt/trading_service_rust/data/account.csv` | 账户配置（编辑后经 reload 接口热加载） |
| `/opt/trading_service_rust/data/account.key` | 账户主密钥（32 字节 raw，0600） |
| `/opt/trading_service_rust/data/south.key` | 南向 HMAC 密钥（0600，首启自动生成） |
| `/opt/trading_service_rust/data/{日期}/...` | 订单/持仓 CSV 数据（自动生成） |
| `/opt/trading_service_rust/logs/trading-service.log` | 服务日志（append） |

权限模型：**root 只在安装这一刻出现**。安装目录属主是执行 `sudo` 的真实用户，
后续编辑配置、看日志、查数据全部用普通用户即可；仅 systemd 的
start/stop/restart 需要 sudo（管理入口 `trading-service restart` 内部已带）。

**升级与卸载**：`git pull` 后重跑部署脚本即升级（二进制重装、配置/数据不动，
`account.csv` 与 `*.key` 不存在才会创建）；卸载用 `deploy/uninstall.sh`
（默认保留 data/，`--purge` 才连数据一起删）。升级后执行
`sudo /opt/trading_service_rust/bin/start.sh` 使新二进制生效（`deploy.sh` 不自动重启）。
系统上留下的只有 `/opt/trading_service_rust` 一个目录、一个 systemd 单元、一个软链。

## 3. 部署步骤

### 3.0 一键部署（推荐）

clone 项目后，在项目根目录执行：

```bash
sudo ./deploy/deploy.sh
```

> `deploy.sh` **只安装**：不会 `enable`、不会启动服务；配置完成后用 `bin/start.sh` 启动。

脚本自动完成（全部幂等，可重复执行）：

1. `cargo build --release --features ctp` 构建 trading-service 与 account-tool；
2. 安装二进制到 `/opt/trading_service_rust/bin/`（含 `start.sh`）；
3. 安装 CTP 运行库 `thosttraderapi_se.so` / `thostmduserapi_se.so` 到
   `/opt/trading_service_rust/lib/ctp/`；
4. 安装交易所配置 `/opt/trading_service_rust/conf/venue.toml`（已存在则跳过，不覆盖调优）；
   **首次安装**会把 `[ctp] trader_so/md_so` 指向上述 `lib/ctp/` 路径；
5. 初始化数据目录 `/opt/trading_service_rust/data`：`account.csv` **不存在则只创建表头、存在则不动**（保留真实凭证）；
6. 创建日志目录 `/opt/trading_service_rust/logs`；
7. 由 `deploy/trading-service.service`（首次从 `.example` 复制）生成
   `/etc/systemd/system/trading-service.service`，
   其中 `User=` 自动替换为执行 `sudo` 的真实用户，其余路径为脚本固定 FHS 路径；
8. `daemon-reload`（**不 enable、不启动**）。

部署后请按顺序完成（此时服务尚未启动）：

1. **添加账户**（逐项提问、secret 不回显、写入前自动加密；CTP 选 `exchange=ctp`）：
   `/opt/trading_service_rust/bin/account-tool add-account`
   （也可手工编辑 `data/account.csv`，或走 `trading-service account` 管理入口。）
2. **配置 CTP 前置与账号名（脚本不修改）**：编辑 `/opt/trading_service_rust/conf/venue.toml`
   的 `[ctp]`，设置 `md_front = "tcp://<柜台行情前置>:<端口>"` 与
   `md_account = "<account.csv 中的 name，逐字符一致>"`。
   （仓库默认可能带有其他环境的旧值，请按本机柜台替换。）
   `md_front` 为空时 CTP 行情线程不会启动（交易仍可能通过账户 `front_address` 建连，
   但 tick/K线不可用）。修改 `[ctp]` 后重跑 `start.sh`（会 restart；venue.toml 不热加载）。
3. **启动服务**：`sudo /opt/trading_service_rust/bin/start.sh`
   该脚本执行 `daemon-reload + enable + restart`；启动后账户增改用
   `trading-service reload`（无需重启）。

可选：需要企业微信播报时，编辑
`/etc/systemd/system/trading-service.service` 中的五个 `REPLACE_WITH_*_WEBHOOK`
（通道语义见 §3.4），然后 `systemctl daemon-reload && sudo /opt/trading_service_rust/bin/start.sh`。
**已填过的 webhook 在重跑部署脚本时会被自动保留**（脚本从旧单元提取非占位符的
URL 回填到新生成的单元），无需每次重填。

以下小节为一键脚本各步骤的手工等价操作说明（排查问题或想自定义路径时参考）。

### 3.1 构建 release 二进制（脚本步骤 1 的手工等价）

在项目根目录：

```bash
cargo build --release --features ctp -p trading-service --bin trading-service
# 同时构建加密工具（下一步要用；CTP feature 一起编入不影响）
cargo build --release --features ctp -p trading-service --bin account-tool
```

### 3.1.1 CTP 部署前置（Debian/Ubuntu，x86_64）

`deploy.sh` **只检查、不自动安装**以下依赖；请先用部署用户完成：

```bash
sudo apt update
sudo apt install -y build-essential clang libclang-dev pkg-config curl libstdc++6
# Rust >= 1.80（用部署用户安装，deploy.sh 会从 /home/<用户>/.cargo/bin 查找）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
```

- 仅支持 **x86_64 Linux**（仓库内 CTP `.so` 是 x86-64 ELF）；
- CTP 前置是裸 TCP，不走 `http_proxy`，需保证机器能直连柜台前置；
- `deploy.sh` 自动完成：`--features ctp` 构建、安装两个 `.so` 到
  `/opt/trading_service_rust/lib/ctp/`、首次部署时把 `[ctp] trader_so/md_so`
  写入 `conf/venue.toml`；
- `md_front` / `md_account` 不由脚本修改（见 §3.0 部署后步骤第 2 步）；
- `deploy.sh` 只安装不启动；配置并添加账户后执行
  `sudo /opt/trading_service_rust/bin/start.sh`；
- CTP 账户的 `credentials` JSON 需包含 `broker_id/user_id/password/app_id/auth_code/
  investor_id/front_address/is_production_mode`，示例见 §3.2。

### 3.2 准备账户文件（脚本步骤 4 的手工等价）

编辑 `/opt/trading_service_rust/data/account.csv`（一键脚本已创建仅含表头的文件；
表头同 `deploy/account.example.csv`）。新 7 列格式：公共列 + `credentials`
整串凭证 JSON（按 exchange 选 schema；REST 所 `is_testnet`/`position_mode`
即在此 JSON 内，生产账户保持 `is_testnet:false`）。推荐直接用 `add-account`
逐条写入（自动校验 + 加密），也可手工编辑后用 `encrypt` 加密：

```csv
id,name,exchange,credentials,deleted,created_at,updated_at
0,prod_deribit,deribit,enc.v1.x8Fk2Q…,0,0,0
```

CTP 行的 credentials JSON 示例（明文形态，写入前会被整串加密）：

```json
{"broker_id":"9999","user_id":"100001","password":"pwd","app_id":"simnow_client","auth_code":"0000…","investor_id":"","front_address":"tcp://182.254.243.31:40001","is_production_mode":false}
```

CTP 账户的 `name` 必须与 `conf/venue.toml` 的 `[ctp].md_account` 完全一致：

```bash
/opt/trading_service_rust/bin/account-tool add-account \
  --name '<account_name>' --exchange ctp \
  --credentials '{"broker_id":"9999","user_id":"100001","password":"pwd","app_id":"simnow_client","auth_code":"0000","investor_id":"","front_address":"tcp://1.2.3.4:40001","is_production_mode":false}'
```

### 3.3 生成主密钥并加密 credentials（生产必须）

account-tool 与服务二进制同仓构建，`deploy.sh` 会一并安装到
`/opt/trading_service_rust/bin/account-tool`；以下为手工等价操作：

```bash
cargo build --release -p trading-service --bin account-tool
sudo install -m 0755 target/release/account-tool /opt/trading_service_rust/bin/account-tool

# 1) 生成 32 字节主密钥（0600）到数据目录
sudo /opt/trading_service_rust/bin/account-tool gen-key --key /opt/trading_service_rust/data/account.key

# 2) 追加账户：写入前按 exchange 校验 credentials JSON 并整串加密（原子回写）
sudo /opt/trading_service_rust/bin/account-tool add-account \
  --csv /opt/trading_service_rust/data/account.csv \
  --key /opt/trading_service_rust/data/account.key \
  --name prod_deribit --exchange deribit \
  --credentials '{"api_key":"KEY","api_secret":"PLAIN","position_mode":"one_way","is_testnet":false}'
```

- `credentials` 已是 `enc.v1.*` 或空值会自动跳过加密；可重复执行。
- 也可只加密单个值：
  `account-tool encrypt --key /opt/trading_service_rust/data/account.key --secret '明文'`
- 旧宽表格式（含 `api_key` 列）的存量文件须先迁移（见 §4.2）。
- **务必备份 `/opt/trading_service_rust/data/account.key`**：丢失后已加密的 credentials 无法解密。
- 若希望由服务首启自动生成 account.key / south.key，亦可直接启动服务；
  但生产建议先用 account-tool 生成并备份主密钥。

### 3.4 配置企业微信通知（五个 webhook）

在企业微信中，对目标群：群设置 → 群机器人 → 添加机器人 → 复制 webhook
（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`）。

| 参数 | 触发时机 |
|---|---|
| `--notify-open-url` | **开仓成交**播报 |
| `--notify-close-url` | **风控平仓成交**播报 |
| `--notify-test-url` | **Deribit 订单状态播报 / 仓位定时播报**（整点对齐） |
| `--notify-manual-close-url` | **需人工处理**告警（如期权平仓价差过宽无法自动平；未配置时回退 close-url） |
| `--notify-position-url` | **Deribit 订单事件播报**（通知 A，独立通道） |

- 各通道可填**同一个生产群机器人**，也可分别发到不同群；留空（默认）即关闭该通道。
- 请使用**生产专用机器人**，不要沿用测试 key。

### 3.5 用 systemd 托管（脚本步骤 5–7 的手工等价）

单元模板为 `deploy/trading-service.service`（首次部署时由脚本从
`deploy/trading-service.service.example` 复制而来；`User=` 为占位，脚本会替换；
路径固定为上表 /opt 布局）。后续自定义配置（如监听地址 `--south-addr`、webhook）
直接编辑该 `.service` 文件，重跑部署脚本即生效；该文件不入库（.gitignore）。

服务日志**直接写固定文件**（append，重启不丢历史），日志目录由部署脚本创建；
手工部署时需先建好并确保运行用户可写。CTP 运行库（`lib/ctp/*.so`）与
`[ctp] trader_so/md_so` 注入由 `deploy.sh` 自动完成；手工部署请照 `deploy.sh`
中“安装 CTP 动态库 / inject_ctp_so_paths”步骤执行。

```bash
# 1) 创建目录（把 <用户> 换成实际运行用户）
sudo mkdir -p /opt/trading_service_rust/{bin,conf,data,logs,lib/ctp}
sudo chown -R <用户>:<用户> /opt/trading_service_rust

# 2) 安装二进制与配置
sudo install -m 0755 target/release/trading-service /opt/trading_service_rust/bin/
sudo install -m 0755 target/release/account-tool /opt/trading_service_rust/bin/
sudo install -m 0755 deploy/start.sh /opt/trading_service_rust/bin/
install -m 0644 config/venue.toml /opt/trading_service_rust/conf/

# 3) 生成单元（把 <用户> 换成实际运行用户）并安装
sed "s/^User=.*/User=<用户>/" deploy/trading-service.service \
  | sudo tee /etc/systemd/system/trading-service.service >/dev/null
sudo systemctl daemon-reload
# 账户与 [ctp] 配置完成后启动（deploy.sh 只安装，不启动）
sudo /opt/trading_service_rust/bin/start.sh
sudo systemctl status trading-service

# 4) 实时查看日志文件
tail -f /opt/trading_service_rust/logs/trading-service.log
```

日志文件路径为 `/opt/trading_service_rust/logs/trading-service.log`。
`append:` 方式需 systemd ≥240（Ubuntu 24.04 为 systemd 255，支持）。

启动日志应看到 `south HMAC auth enabled`，且**没有** dev-insecure /
明文 secret 告警。

> 日志会持续追加、不自动轮转。建议用 logrotate 按天/按大小切割，
> 避免文件无限增长（需要时在 `deploy/` 下补充 logrotate 配置）。

> 注意：服务用 `--south-addr 127.0.0.1:9100` 仅绑定本机回环,
> 不要直接暴露到公网，由下面的反向代理对外提供 wss。

### 3.6 反向代理终结 TLS（wss）

生产必须经 TLS 承载，防止南向密钥在传输中被窃听/篡改。

Nginx 示例：

```nginx
location /ws {
    proxy_pass http://127.0.0.1:9100;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}
```

Caddy 示例（自动证书）：

```
your-domain.com {
    reverse_proxy 127.0.0.1:9100
}
```

### 3.7 上线验证（小额）

1. 用真实生产账户经南向 wss 发一笔**小额**单；
2. 确认：订单成交、企业微信**生产群**收到播报、持仓正确回写；
3. 再验证一次平仓与对应播报。

### 3.8 健康检查与运维接口

<!-- AUTO-GENERATED: 来源 crates/trading-service/src/main.rs 与 src/api/mod.rs，路由变更时同步 -->

REST 与南向 WS **共用 `--south-addr` 同一端口**（默认 `127.0.0.1:9100`）。经反向代理暴露时，
`/ws` 需 WebSocket upgrade，其余按普通 HTTP 转发。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 存活检查，裸报文 `{"status":"healthy"}`（无 `code/message/data` 信封） |
| GET | `/api/v1/state` | 服务状态摘要 |
| GET | `/api/v1/accounts` | 账户安全投影（不含密钥） |
| GET | `/api/v1/positions`、`/api/v1/positions/{id}` | 仓位查询 |
| GET | `/api/v1/orders` | 订单查询 |
| GET | `/api/v1/rules` | 规则查询 |

#### 常见排查

- 部署后服务未启动：`deploy.sh` 只安装不启动；执行 `sudo /opt/trading_service_rust/bin/start.sh`。
- 启动日志出现 `ERROR ... 南向鉴权处于 --south-dev-insecure 旁路模式`：仅本地联调允许，生产必须去掉该参数。
- `Address already in use`：旧进程未退；`ss -ltnp | grep 9100` 定位后停止对应进程。
- CTP 日志 `行情兴趣集为空，保活等待`：当前无合约订阅时的正常保活（5s 重查），订阅后自动建连，不是故障。
- CTP 日志 `failed to open` / `.so` 加载失败：确认 `/opt/trading_service_rust/lib/ctp/`
  下两个 `.so` 存在，且 `conf/venue.toml` 的 `[ctp] trader_so/md_so` 指向它们；
  不要依赖编译期路径。
- CTP 行情线程未启动 / 日志提示缺账户名：确认 `[ctp].md_account` 与 `account.csv` 的
  `name` **逐字符一致**（下划线/连字符敏感），且该账户 `exchange=ctp`。
- `/admin/ctp/refresh-specs` 返回 404：当前二进制未以 `--features ctp` 构建，重跑
  `deploy.sh`（已默认带该 feature）。
- CTP 前置连接超时：CTP 走裸 TCP，不经过 `http_proxy`/`https_proxy`；检查机器到
  `md_front` / 账户 `front_address` 的网络与防火墙。
- K线不落盘：核对 `--kline-flush-interval` 非 0、`--data-dir` 可写，以及
  `config/venue.toml` 中 `[ctp].kline_products` / `[binance].kline_symbols` 是否覆盖目标品种。
- 日志出现 `ERROR ... 持久化 bar sink 缺失（疑似被 panic 摘除），已重新注册`：持久化 sink
  曾 panic 并在下一拍自愈；结合上一条 `WARN ... 无条件 bar sink panic` 排查上游。旧版本曾因
  单次回调 >1ms 把落盘 sink 永久摘除；新版本慢回调只打一次 WARN（`仅告警不摘除`），不影响落盘。

## 4. 上线后如何新增 / 修改账户（无需重新编译、无需重启进程）

账户与程序二进制相互独立：**增删账户只需改 `/opt/trading_service_rust/data/account.csv`
（属主是运行用户，普通用户编辑即可），不用重新编译、不用传二进制、不用重启服务。**

> **重要：服务不做文件轮询，光改 account.csv 不会生效。**
> 改完文件后，必须显式调用一次管理接口触发重载：
> `POST /admin/accounts/reload`。
> 该接口重新读取并解密 account.csv、递加重载版本，交易所连接随后在下一
> 对账周期自动“停旧起新”。

### 4.1 新增账户步骤

**方式一（推荐）：account-tool 交互式添加**（提问补齐各项、secret 不回显、
写入前即用 account.key 加密、同名账户现场询问是否覆盖）：

```bash
/opt/trading_service_rust/bin/account-tool add-account
# 脚本/CI 场景可全部用参数直传（--csv/--name/--exchange/--api-key/--secret/--key）
```

**方式二：手工编辑**——先用 account-tool 加密 secret（必须用生产机现有的
`/opt/trading_service_rust/data/account.key`，否则服务解不开）：

```bash
/opt/trading_service_rust/bin/account-tool encrypt \
  --key /opt/trading_service_rust/data/account.key \
  --secret '新账户明文secret'
# 复制输出的 enc.v1.xxx，再编辑 data/account.csv 追加一行（生产 is_testnet=0）：
# 1,new_account,deribit,API_KEY,enc.v1.xxx,,one_way,0,0,0,0
```

3. **调用管理接口触发重载（必须）**：

   ```bash
   trading-service reload
   # 或 curl -X POST http://127.0.0.1:9100/admin/accounts/reload
   # 返回 {"success":true,"accounts":N,...} 即成功
   ```

   > 该接口当前无独立鉴权，因此务必在生产机本机用 127.0.0.1 调用，
   > 且 9100 端口不对公网暴露。

4. 用新账户发一笔小额单验证其可用。

### 4.2 旧宽表 account.csv 迁移为新 7 列格式（升级必读）

从旧版本（含 `api_key`/`api_secret` 等宽表列）升级时，服务会**拒载**旧格式并
提示迁移；用 `account-tool migrate` 一次性转换（原文件自动备份 `.bak`）：

```bash
# 逐行按 exchange 拼 credentials JSON 并整串加密（已是密文的旧 api_secret
# 列会被解密还原后再整体加密；无 --key 且旧列有密文时报错）
/opt/trading_service_rust/bin/account-tool migrate \
  --key /opt/trading_service_rust/data/account.key \
  --csv /opt/trading_service_rust/data/account.csv

# 迁移完成后必须触发重载
curl -X POST http://127.0.0.1:9100/admin/accounts/reload
```

重载后服务用同一把 account.key 解密，连接行为不变。用 `.bak` 与新文件 diff
核对账户数与字段无误后，再删除备份。

### 4.3 注意事项

- **account.key 必须妥善备份**：它是解密所有 credentials 的唯一主密钥，
  丢失后密文无法还原。
- 加密与服务必须使用**同一把 account.key**；不要拿别的机器的 key 加密后拷过来。
- 数据目录 `/opt/trading_service_rust/data` 独立于代码仓库；切勿把账户文件或密钥拷入项目目录提交。
- 程序升级（重跑部署脚本更换二进制）不影响 `/opt/trading_service_rust/data`。
